# A modular C++ simulation of satellite attitude dynamics and a PD controller, with sensor noise, angle wrapping, CSV telemetry, and Python plotting.

# What this project demonstrates
    * Flight software structure (modular C++, clear interfaces, testing)
    * Basic GNC (PD attitude control)
    * Sensor noise vs. true state
    * Data logging to .csv
    * Automated gain tuning via grid search

# How to run simulation and plotting (make sure you are in main folder)
.\build.ps1

# How to run manually
g++ -std=c++17 -Iinclude src/*.cpp -o attitude_sim.exe
.\attitude_sim.exe              # uses default gains
.\attitude_sim.exe 54 41        # custom gains

# To plot results
python python/plot_results.py

# To tune gains
python python/tune_gains.py

# Current behavior
    * PD controller (default gains can be overridden from the command line)
    * Sensor noise on measurements only (true dynamics stay clean)
    * Attitude error wrapped to [-pi, pi]
    * Logs true state to telemetry.csv
    * Python grid-search tuner for `kp` and `kd`

# Results
    Automated grid search and manual evaluation were used to tune the controller. A high-performance set is `kp = 54` and `kd = 41`. With these gains the satellite settles to the commanded attitude in roughly 3 seconds with minimal overshoot.

    Higher gains produce faster response but also make the controller more sensitive to sensor noise, which appears as small high-frequency jitter in the rates after settling. This is a classic control tradeoff. The figure `attitude_response.png` (generated by `plot_results.py`) shows this behavior.

    The closed-loop system remains stable and reaches the target even in the presence of measurement noise.
